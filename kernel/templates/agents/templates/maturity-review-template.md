# Maturity Review

## Project State

Describe whether this is no-code, prototype, early product, mature project,
legacy project, or rescue project.

## Existing Code

Summarize the current implementation.

## Existing Architecture

Summarize architecture and whether broad changes are appropriate.

## Existing Tests

Summarize test and verification coverage.

## Existing Deployment

Summarize deployment state and blockers.

## Recommendation

State the harness posture: preserve, rescue, refactor cautiously, or build from
source.

## Rules

- For mature projects, avoid broad architecture changes unless the user asks.
- For immature projects, propose focused ways to bring the project to the next
  quality level.
- For projects without code, derive the harness from source documents and user
  answers.
